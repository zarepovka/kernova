# Kernova

Учебный прототип собственного ядра для 32-битной x86 на C и ассемблере.

## Что реализовано

- Заголовок Multiboot и точка входа `_start` для загрузки через GRUB.
- Вызов функции ядра `kernel_main` из ассемблера.
- Запись сообщения напрямую в текстовую видеопамять VGA по адресу `0xB8000`.
- Makefile для сборки образа ISO и запуска в QEMU.

Проект находится на раннем этапе: клавиатура, командная оболочка, файловая система и управление памятью пока не реализованы.

## Структура

```text
src/boot.s          # Заголовок Multiboot и точка входа
src/kernel.c        # Вывод сообщения в видеопамять
boot/grub/grub.cfg  # Конфигурация GRUB
Makefile            # Команды сборки и запуска
Dockerfile          # Исходная заготовка окружения
```

## Сборка

Makefile ожидает инструменты `x86_64-elf-gcc` с поддержкой `-m32`, `x86_64-elf-ld` с поддержкой `elf_i386`, `grub-mkrescue`, `xorriso` и QEMU (`qemu-system-x86_64`).

```sh
make
make run
```

Ожидаемый путь к образу: `build/kernova.iso`. Очистка результатов сборки: `make clean`.

## Статус и известные ограничения

При публикации выполнено переименование проекта; функциональность исходного прототипа сохранена. Сборка и загрузка в эмуляторе не проверены.

- Dockerfile устанавливает обычный GCC, но Makefile вызывает кросс-компилятор `x86_64-elf-gcc`: исходное окружение требует согласования.
- Ядро линкуется как плоский бинарный файл; совместимость такого образа с текущим заголовком Multiboot требует проверки.
- Перед вызовом C-функции собственный стек не настраивается.
- Прямая запись UTF-8 и символа перевода строки в VGA не обеспечивает корректный вывод русского текста и перенос строки.
- Цель ISO в Makefile отличается от пути создаваемого файла, поэтому повторный `make` может пересобирать образ.

Сгенерированные ISO, объектные и бинарные файлы в репозиторий не включены.
